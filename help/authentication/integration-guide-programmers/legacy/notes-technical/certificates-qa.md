# （レガシー）証明書に関するQ&amp;A {#certificates-q}

</br>

**Q1:** iOSとAndroidで証明書を登録できますか？

**A:** iOSとAndroidの証明書は、現在の設定と同じです。 ネイティブ証明書は両方のプラットフォームで使用されます。

</br>

**Q2:**&#x200B;実稼動環境とステージング環境で、同じiOS証明書をプライマリおよびバックアップ証明書として使用できますか？ お勧めしない場合は、説明してもらえますか？

**A:** プライマリとバックアップの両方の証明書と同じ証明書を設定しても意味がありません。 プライマリ証明書とバックアップ証明書を使用することで、プライマリ証明書が期限切れになったり失効したりした場合に備えて、プログラマに複数の証明書を設定できます。 バックアップ証明書があれば、リリース環境に影響を与えることなく、プライマリを変更する時間がプログラマーに与えられます。 ただし、実稼動プロファイルとステージングプロファイルの両方に同じプライマリ証明書とバックアップ証明書を使用できます。

</br>

**Q3:**&#x200B;新しいフレキシブル TempPassを使用するweb ページに必要な新しい証明書はありますか？

**A:**&#x200B;証明書（および実際に任意の証明書）は、Media CompanyおよびProgrammer レベルで設定されています。 FlexibleTempPassはMVPDであるため、証明書を設定する必要はありません。そのため、既存のProgrammerと柔軟なTempPassを統合する場合は、Programmer/Media Company レベルで既に設定されている証明書が使用されます。
