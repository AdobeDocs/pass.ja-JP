## 概要 {#overview-sso-support}

このドキュメントでは、様々なプラットフォームでAdobe Pass Authenticationによってサポートおよび提供されるシングルサインオンの種類について説明します。 このドキュメントの目的は、サポートされている内容とそうでない内容、各SSO方式のMVPD カバレッジの概要、および各プラットフォームでSSOを利用するためにプログラマーに必要な内容を明らかにすることです。

利用者がMVPDの認証情報を使用してログインすると、Adobe Pass Authenticationは、MVPDの認証セッションを表す安全なトークンを生成し、デバイス IDを使用してそのトークンを利用者のデバイスにバインドします。 Adobe Pass Authenticationは、トークン / デバイス IDをサーバーまたはデバイスに保存します。 これにより、ユーザーはトランザクションを安全に保ちながら、より頻繁に資格情報を入力できるようになりました。

>[!NOTE]
>
>SSO ワークフローは、Premium Workflow パッケージの一部です。 この機能の使用をご希望の場合は、Adobe Passの営業担当者にお問い合わせください。

### Xbox 360およびXbox Oneに関する注意事項 {#notes-xbox-360}

* **Xbox 360**- Xbox 360は、デバイス IDを埋め込むトークンを提供するためにライブサービスに依存しています。 deviceIDのappID値のLive Service レイヤー。アプリにのみスコープが設定されます。 Xbox 360の場合、Microsoftはトークンの解析に役立つJava ライブラリをAdobeに提供しました。

* **Xbox One**- パブリッシャーの証明書/キーで暗号化され、Microsoftによって署名されたJSON web トークンが発行されます。 Adobeは、Xbox 360 パラメーターのPDID （Partner Device ID）とは異なるDPI （Device Pairwise ID）と呼ばれるパラメーターからdeviceIDを抽出します。 PDIDはXbox Oneにも存在しますが、この新しいパラメーター「Device Pairwise ID」（DPI）に置き換えられることを意図しています。


### SSOの無効化 {#disable-sso}

特定の状況では、一部のアプリまたはサイトでは、高度なビジネスケースを満たすためにSSOを無効にしたい場合があります。

* **JSおよびネイティブ SDKの場合** - Adobe Pass認証サポートチームは、依頼者IDとMVPDのペアのSSOを無効にできます。 サイトやネイティブアプリで作業する必要はありません。  Adobe Pass認証サポートチームがSSOを無効にすると、指定したRequestorIdとMVPDのペアを使用して実行した認証は、異なるRequestor IDを使用するサイトやアプリと共有されなくなります。 また、異なる依頼者IDを持つ既存の認証は、SSOが無効にされた依頼者IDとMVPDの組み合わせには有効ではありません。 技術的には、SSOの無効化は、AuthN トークンを特定の依頼者IDとMVPDの組み合わせにバインドすることで行われます。
* **クライアントレス API**&#x200B;の場合 – REST呼び出しで空でないappId パラメーターを指定することで、クライアントレス認証フローでSSOを無効にできます。 任意の文字列を値として使用できます。この文字列は、依頼者IDに対して一意である限り使用できます。 Clientless APIの場合、この依頼者固有のパラメーターを追加するには、プログラマー/実装者がサイトまたはアプリを変更する必要があります。

>[!IMPORTANT]
>
>CLIENTLESS API SSOに関する注意事項：一部のMVPDでは、各ネットワーク（要求者ID）が独自の認証フローを実行する必要があります。 SDK ベースのフロー（iOSなど）の場合、これはSDKによって自動的に処理されます。 ただし、クライアントレス APIの場合は、プログラマが処理する必要があります。 現時点では、クライアントレス APIのSSO フローを有効にせず、代わりにデバイス IDとアプリ IDの組み合わせをデバイス IDに使用することをプログラマーに強くお勧めします。 Adobeでは、適切なSSOを確立できるように、クライアントレス API フローの改善にも取り組みます。

### ログアウト {#logout-sso-support}

プログラマーは、シングルサインオンのコンテキストにおける「ログアウト」アクションが、1つのアプリ/1つのサイトで実行されると、デバイス上のすべてのトークンが削除され、ユーザーがアプリ/サイト間でログアウトされることに注意する必要があります。

SSO条件が満たされた場合（SSOが有効であるか無効であるかに関係なく）、ログアウトが実行され、すべての認証および認証情報が削除されます。
