# Adobe Pass Concurrency Monitoring 2.5.0 リリースノート {#cm-250}

このページでは、このリリースの新機能、変更点、既知の問題について説明します。

リリース日：2016年4月21日（PT）

## 新機能 {#new-features}

同時実行モニタリング API v2.0が実稼動環境で使用できるようになりました。

V2 バージョンでは、ハートビートとクエリ呼び出しが統合され、両方のAPIを同時に使用すると、実装が大幅に簡素化されます。



### セッションのライフサイクル {#session-lifecycle}

* 書き込み専用のAPIを使用して、セッションの作成、維持、終了を行います。つまり、クエリがなくなり、セッションのinit呼び出しとハートビート呼び出しの両方で決定が返されます
* ハートビートインターバルは、セッションのinit呼び出しとkeep-alive呼び出しの両方で設定されたExpires ヘッダーを介してサーバーによって駆動されるようになりました。 これにより、アプリ内のハートビート間隔と1つ未満のハードコード値をサーバーサイドで設定できます。
* ハッピーパス（ユーザーとアプリの両方の準拠した動作）は、2XX ステータスコードで「舗装」されます

### エラー処理 {#error-handling}

* 拒否の決定、メタデータの欠落、またはアプリケーションの不正動作は、4XX応答（競合、不正なリクエスト、不正、行き詰まりなど）としてフラグ付けされます。

* 合理的に考えれば、次のような回答が返ってきます。

  * 関連するアドバイス – ユーザーに対してプロンプトを表示する、失敗の詳細な説明。

  * 義務 – アプリケーションが実行する必要のある必須アクション（例：メタデータの更新、Adobe Passからのログアウト）。

### メタデータ {#metadata}

* カスタムメタデータの代わりに標準 – これにより、APIは、間違ったメタデータが送信されているか、ルールで必要なメタデータが欠落しているかどうかを識別できます。
* 各アプリケーションに必要な属性は、API呼び出しによって提供されるようになりました。クライアントがキャッシュする必要があります。
