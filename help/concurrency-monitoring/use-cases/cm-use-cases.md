# ユースケース {#use-cases}

Stream Counting Serviceの主なユースケースは、ユーザーが視聴した同時動画ストリームの数をカウントし、同じアカウント IDに対する同時使用に関する決定を提供することです。

加入者の使用状況を監視するために、プログラマーのweb サイトやアプリケーション、MVPDのコンテンツポータル、またはシンジケートされたプロパティのいずれで発生しても、ユーザーアクティビティを集約できる一元化されたサービスが必要です。

この一元化されたサービスでサポートされる主なユースケースは次のとおりです。

1. 加入者がビデオの視聴を開始するとすぐに、アプリケーションは&#x200B;**ストリーミングセッションを初期化**&#x200B;し、**レポート活動** データを開始できます。
1. 同じ中央サービスで、別のインスタンスが&#x200B;***CM決定***&#x200B;を受け取ります。アプリケーションに1つ以上のポリシーがCM サービスに登録されている場合、サービスは現在のアクティビティに基づいてアクセス決定を行って応答します。

## 一般的なユースケース {#common-use-cases}

### 基本ストリーム制限

すべてのアプリケーションをまたいで、サブスクライバーあたりの同時ストリーム数を制限します。

### デバイスベースの制限

デバイスの種類（モバイル、タブレット、テレビなど）ごとに一定数のストリームのみを許可します。

### コンテンツ固有のルール

ライブコンテンツとVODコンテンツに対して異なる制限を適用します。

### 位置情報ポリシー

位置情報やネットワークの種類にもとづいてストリーミングを制限。

## セッションの作成 {#create-session}

このAPI呼び出しにより、ユーザーが「再生」ボタンを押してコンテンツを視聴する際に、クライアントは新しいCM セッションを作成できます。 サーバーの応答には、それを維持するための新しいストリーム URL （ストリーム IDを含む）と、ストリームがタイムアウトする時間が含まれます。 クライアントアプリケーションは、ハートビートを通じてアクティビティを報告することが期待されます。 セッション初期化呼び出しは、フォームデータ（またはクエリ文字列パラメーター）として送信されるキーと値のペアの形式でメタデータを含める必要があります。 さらに、応答には、再生が「ポリシーに準拠している」かどうかを示すフラグも含まれます。 そうでない場合、再生は許可されません。

## レポートアクティビティ {#reporting-activity}

セッションを作成したら、そのストリームをアクティブ状態に保つために、アプリケーションはハートビートを定期的に送信する必要があります。 また、タイムアウトまでストリームがアクティブとしてカウントされないように、ユーザーが再生を停止すると、クライアントアプリがストリームを停止することをお勧めします。

ハートビートコールの応答により、クライアントアプリケーションは（ポリシーに準拠している場合に）ビデオ再生を続行したり、ビデオ再生を停止するように指示したりできます。 ビデオストリームが準拠していない場合、クライアントアプリケーションはそれを停止する必要があります。 応答は、クライアントアプリケーションがエラーメッセージやユーザーが再生を続行するための利用可能なアクションを表示するための情報を提供します。
