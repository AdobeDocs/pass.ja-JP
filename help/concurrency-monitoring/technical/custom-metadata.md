# カスタムメタデータ {#cm}

>[!NOTE]
>
> このページは、新しい統合では推奨されなくなった以前のバージョンのAPIに適用されるため、非推奨です

このサービスにより、クライアントはクエリと意思決定の両方で、標準フィールドとカスタムフィールドの両方を使用できます。 標準フィールドは、任意のストリームで常に使用できます（ストリームの作成に必要であるか、サーバーによって生成されるかのいずれかです）。

* アプリケーション
* mvpd
* accountId
* streamId
* streamStart
* 開始者


カスタムフィールドは、ストリームの初期化時に渡されるキーと値のペアで、フォームまたはクエリ文字列のパラメーターとして指定します。 標準フィールドとカスタムフィールドの両方を次のシナリオで使用できます（詳細については、以下の関連するAPI リソースの実際のドキュメントを参照してください）。

* アカウント（/streams リソース）のストリームリストを取得する際の追加フィールド（fields クエリ文字列パラメーターを介した）のリクエスト
* グループ化するディメンション（/activity リソース）を指定して、アカウントアクティビティを分類する
* フィールド値または基数に基づくサーバーサイドポリシーの定義（例では、わかりやすくするために疑似SQLを使用しています）:
* 特定のフィールド値にのみ適用するようにポリシーを設定します（例：専用のiOS ポリシー：OSTypeは「iOS」）。
* 特定のフィールドの異なる値の数を制限します（例：X個を超えないデバイス：HAVING DISTINCT COUNT （deviceId） >= 2）。
* フィールド値あたりのアクティブストリーム数を制限します（例：単一デバイスタイプのアクティブストリーム数はX以下です：GROUP BY deviceType HAVING COUNT （streamId） >= 3）


送信されるこれらのキー/値に基づいて、異なるルールを確立できます。 これは、次のような文章に沿ったものかもしれません。

1. お客様は、パラメータ群を送信することを決定します。これは、値「SPORTS」と「KIDS」として持ちます。
1. 次に、アプリはこれを行う必要があります。
   * スポーツチャネルの場合、ストリームの初期化時に、アプリはクエリパラメーターとして&#x200B;***type=SPORTS***&#x200B;を送信します
   * 子ども関連コンテンツを含むチャネルの場合、ストリームの初期化時に、アプリはクエリパラメーターとして&#x200B;***type=KIDS***&#x200B;を送信します
1. 次に、このようなポリシーを定義できます。
   * `GROUP by type HAVING COUNT(streamID) < 4) IF type=KIDS`
   * `GROUP by type HAVING COUNT(streamID) < 2) IF type=SPORTS`
1. これは基本的に、ユーザーがスポーツを観戦している場合、1つ以上のデバイスで視聴することはできませんが、子供のコンテンツを視聴する場合、最大3つのデバイスで視聴が許可されます。
